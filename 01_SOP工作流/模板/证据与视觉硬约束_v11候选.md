# 证据与视觉硬约束（v11 候选，2026-11-11）

> 来源：Anthropic 路演篇（`15_Anthropic路演_案例/复盘_2026-11-11_歧义与约束.md`）暴露的 17 个问题。
> 定位：**SOP v10 的补丁，不改 v10 已写的内容规则**；等流水线优化那一轮收尾后并入 SOP v11。
> 适用：所有「把视频/播客/文件加工成公众号稿件」的稿子；其中 C01–C05 适用于任何配图，C10–C12 适用于任何走 `gzh_pipeline.py` 的稿子。
> 使用方式：开工前读一遍；定稿前按 §三 的检查表自检；机器可查项用随附脚本。

## 一、硬约束（按触发条件执行）

### A. 配图与证据

| ID | 触发 | 约束（必须做） | 验收方式 |
|---|---|---|---|
| C01 | 任何「引用原始材料」的配图 | **不得重绘、不得重排原始数据**。图表、条款表、财务报表一律用原帧截图；作者的解读只写进正文，不画进图里 | 逐图问：这张图的每个数字/坐标是否都能在原帧上找到？找不到就删图或改成文字 |
| C02 | 重绘/统计图（仅限「作者分析图」，且原页不存在该视图） | 不得改变刻度、坐标原点、时间窗口、口径。用对数刻度必须图内明示，且不得用于「增速对比」类叙事 | 图内标注刻度类型 + 数据源；编辑复核「换成线性刻度后结论是否还成立」 |
| C03 | 转写稿与画面数字不一致 | 数字**以画面原页为准**；转写稿只用于定位与检索。口述与幻灯片不一致时，正文写「约/接近」并给画面口径 | 台账每个数字标「画面/语音」来源；不一致处单列一行 |
| C04 | 从视频抽帧 | 抽完**立即看图**确认内容与信息完整度（动画页取信息齐全帧），再按「内容+时间码」命名；不得按时间点盲命名 | 文件名与图注内容一致；动画页单独记录「为何选这一帧」 |
| C05 | 图注写「原帧/未处理」 | 必须写清处理链：取帧 → 是否缩放 → 是否锐化 → 压缩质量。「原帧」只用于未做几何变换的图；裁切/放大必须写「局部裁切」「N 倍放大」 | 图注四要素齐全；出现「原帧」二字时能对上处理链 |
| C06 | 写人名、职务、头衔 | 只认**画面姓名条 / 官方页面 / 一手文件**。转写稿的说话人切分不可信；推断不出就用角色表述（「财务负责人」「一位客户」）或不引用 | 台账 V 组逐行给定位；无定位的名字删除 |
| C07 | 使用二手报道（播客拆解、媒体转述） | 核心数字必须一手（招股书/公告/公司页面）；二手只能出现在「分歧、背景、对照」位置，句内标「据 XX」，不得做判断句的主证据 | 正文每个二手信息有「据」字；交付清单列「待回原始文件核对」 |
| C08 | 正文自指数量（「N 张图」「N 处原话」「N 位出镜者」） | 必须能逐项列出；列不全就改「几张/多处/多位」。定稿前用脚本数一遍 | 自检脚本 `check_figures_quotes`：图数、引语块数、说话人数与正文数字一致 |

### B. 写作与口径

| ID | 触发 | 约束 | 验收 |
|---|---|---|---|
| C09 | 估算、推算、跨页计算 | 正文同屏给算式与口径；标题、封面、首屏带「约/估算」；非 GAAP 数字必须带「调整后」，且与 GAAP 同屏各出现一次 | 全文搜「估算/计算/约」；非 GAAP 段落有对照 |
| C10 | 标题、封面、图注里的数字 | 与正文同口径、同强度；不得比正文更确定（正文「接近」→ 标题不能写「达到」） | 逐条比对标题/封面文案与正文原句 |
| C11 | 正文出现「首先/最后/第一/第二…」等序列 | 序列必须真的穷尽并列项；不得用序列词制造并不存在的结构 | 人工读一遍；删掉不承载信息的序列词 |

### C. 排版与工程

| ID | 触发 | 约束 | 验收 |
|---|---|---|---|
| C12 | 正文使用本地图片且要走 `gzh_pipeline.py` 渲染 | 先内联 base64 再渲染（测量页在 `/tmp`，相对路径必然 NOT_LOADED）；长期方案：流水线加 `<base href>` 或渲染前转绝对 `file://` | 渲染三档无 `NOT_LOADED`；否则判定 INCOMPLETE，不得放行 |
| C13 | 写 `## 来源与说明` | 条目连续行、**不空行**（空行即结束来源区）；说明段用空行隔开；归属声明必须在文末来源区 | 渲染后目检尾屏：来源字样号一致、[2][3] 未掉进正文 |
| C14 | 改版任何交付物（正文/HTML/封面/图） | 先归档旧文件（`_vN` 或说明后缀）再写新文件；无后缀名 = 当前版，README 必须指明 | `ls` 能看到历史版；README 与文件一致 |
| C15 | 中间产物（`_内联版.md`、渲染图、测量页） | 由脚本生成，不手改；文件名与源文件对应；进正文前必须回到源文件改 | 脚本可重跑并复现 |

### D. 封面与视觉

| ID | 触发 | 约束 | 验收 |
|---|---|---|---|
| C16 | 做封面 | 先给 2–3 个方向（纯人物 / 人物+产品界面 / 纯品牌或符号）让用户选，再定稿；不要一次押注某个「主题元素」 | 交付时至少两版可选；用户选定后才做细节 |
| C17 | 封面交付 | 必出 2.35:1 + 1:1 两版；1:1 版不得依赖 2.35:1 的裁切 | 两版都能独立看懂标题与主体 |
| C18 | 封面上出现产品界面、他人作品 | 只能用原帧/授权素材；不得生成界面、不得伪造对话；处理只限缩放、圆角、描边、投影 | 素材来源记录到图源文档；界面文字未被修改 |

### E. 流程与协作

| ID | 触发 | 约束 | 验收 |
|---|---|---|---|
| C19 | 工作区有未提交改动（尤其流水线/orchestrator） | 不跑编排链路；内容按 SOP 手工执行；渲染用 `git show HEAD:` 的已提交版本；不修改他人正在改的文件 | 交付说明写清「用了哪个版本、为什么」 |
| C20 | 用户只丢来素材、没说交付形态 | 先复述三点假设（交付物 / 长度 / 平台）并等确认；用户不答就产出**最小可见件**（大纲或首节），不猜大形态 | 交付说明列出假设 |
| C21 | 非访谈类稿（行业事件型/财报型/文件解读型）且说话人 ≥5 | 可不建人物简介卡；但必须在导语或文末给**说话人清单**（姓名/角色/时间码落差），台账保留身份行 | 读者能在正文前知道谁在说话；台账 V 组完整 |
| C22 | 交付状态描述 | 三态唯一：**本地完成 / 编辑器已验证 / 已发布**。未做编辑器保存与手机预览的，不得写「可发布」 | README 状态行与产物逐项对应 |

## 二、开工前 60 秒（贴在工位上的版本）

1. 素材是什么类型？访谈 / 行业事件 / 文件解读 —— 决定要不要人物卡、要不要中英对照。
2. 画面里有哪些数字？先建「画面台账」，再看转写稿。
3. 配图只用原帧；要可读就写进图注与正文，不重画。
4. 正文里所有「N 张/N 处/N 位」都能数出来。
5. 封面先给方向，不押注；出 2.35:1 + 1:1。
6. 本轮有没有别的人在改仓库？有 → 不跑编排，用 HEAD 版本。

## 三、定稿前检查表（勾完再交）

- [ ] 每张图都问过「原帧能对上吗」，没有作者重绘（C01/C02）
- [ ] 每个数字都标了「画面/语音」来源，冲突处写了「约」（C03）
- [ ] 抽帧都看过图、帧名与内容一致、动画页取的是信息完整帧（C04）
- [ ] 图注写了处理链（C05）
- [ ] 人名职务都有定位，没有推断（C06）
- [ ] 二手信息都带「据」，没有当承重墙（C07）
- [ ] 自指数量数过一遍（C08）
- [ ] 估算有算式，非 GAAP 有「调整后」，标题不超强度（C09/C10）
- [ ] 本地图已内联、渲染三档无 NOT_LOADED（C12）
- [ ] 来源区无空行、归属声明在（C13）
- [ ] 改版的旧文件已归档（C14）
- [ ] 封面两版、素材为原帧或授权（C16–C18）
- [ ] 交付状态用的是三态之一（C22）
