# 字幕定位抽帧 · 操作细则

> 目的：让每张图都精确对应文中的一句"金句"，杜绝画面与内容偏移。

---

## 为什么顺序要倒过来

| | 做法 | 结果 |
|---|---|---|
| ❌ | 抽帧 → 挑不糊的 → 配文字 | 图和内容无关，读者觉得"配图是装饰" |
| ✅ | 定金句 → 定位时间戳 → 抽帧 | 图是证据，不是装饰 |

---

## 前置条件

**转录结果必须带时间戳。** 检查 `transcript.json`：

```bash
python3 -c "
import json
d = json.load(open('transcript.json'))
segs = d['segments'] if 'segments' in d else d
print('段落数:', len(segs))
print('样例:', {k: segs[0][k] for k in list(segs[0])[:4]})
"
```

必须能看到 `start` / `end` 字段。没有的话转录方式要换（见 SOP 第一步）。

## 操作流程

### Step 1 标金句

写完正文后，标出 3-4 句"读者可能想截图转发"的句子。标准：具体、有信息量、带她的原话。

### Step 2 定位时间戳

```python
import json, re, difflib

segs = json.load(open('transcript.json'))
if isinstance(segs, dict): segs = segs['segments']

def find_time(keyword, window=3, threshold=0.55):
    \"\"\"在逐字稿里模糊匹配关键词，返回最相似片段的起始时间\"\"\"
    best = None
    for i in range(len(segs) - window + 1):
        chunk = ''.join(s['text'] for s in segs[i:i+window])
        # 去标点后比对
        clean_a = re.sub(r'[^\w]', '', keyword)
        clean_b = re.sub(r'[^\w]', '', chunk)
        ratio = difflib.SequenceMatcher(None, clean_a, clean_b).ratio()
        if best is None or ratio > best[0]:
            best = (ratio, segs[i]['start'], chunk)
    if best and best[0] >= threshold:
        return best[1], best[2]
    return None, None

for kw in ["押注单一确定性", "不是让AI替代人", "手写笔记本"]:
    t, txt = find_time(kw)
    if t:
        h = int(t // 3600); m = int(t % 3600 // 60); s = t % 60
        print(f"[{int(h):02d}:{int(m):02d}:{float(s):06.3f}] {txt[:40]}")
    else:
        print(f"[未匹配] {kw} —— 换一个更短的关键词，或手动翻逐字稿")
```

### Step 3 抽帧

**取时间戳前 1.5 秒**——说话前的自然表情优于说话中。

```bash
# 基础抽帧
ffmpeg -ss 00:14:23.5 -i input.mp4 -frames:v 1 -q:v 2 frame_1.jpg

# 源视频清晰度不足时：2 倍放大 + 轻度锐化
ffmpeg -ss 00:14:23.5 -i input.mp4 -frames:v 1 \
  -vf "scale=iw*2:ih*2:flags=lanczos,unsharp=5:5:0.8:5:5:0.0" -q:v 2 frame_1.jpg
```

**肖像专用（3:4 竖版，裁正面）**：

```bash
# 先抽一帧看构图
ffmpeg -ss 00:02:15 -i input.mp4 -frames:v 1 -q:v 2 probe.jpg
# 确认构图后按 3:4 裁剪（w=ih*3/4）
ffmpeg -ss 00:02:15 -i input.mp4 -frames:v 1 \
  -vf "crop=ih*3/4:ih,scale=720:960:flags=lanczos" -q:v 2 portrait.jpg
```

### Step 4 逐帧质检

打开每张图，逐条确认：
- [ ] 表情自然（不是说话中途的怪表情）
- [ ] 没有字幕条挡住脸
- [ ] 不是半张脸 / 背对镜头
- [ ] 没有过曝、糊、字幕残留
- [ ] 竖版肖像裁到了头肩，不要裁太松

不合格就换时间戳重抽，**不要将就用**。

## 清晰度：真实原因与实测数据

豆包给的截图糊，主因通常是**源视频本身清晰度 + 平台二次压缩**，不是抽帧工具。

优先级：
1. 从**原始视频文件**抽帧，不要用已下载的压缩版
2. 避开运动模糊帧（说话时头部晃动最容易糊）
3. AI 超分（Real-ESRGAN）——会"编"出合理纹理，但人脸慎用

---

## 📊 锐度检测（不要凭肉眼，跑一次数值）

```python
from PIL import Image; import numpy as np, glob

for f in sorted(glob.glob('截图/*.jpg')):
    g = np.asarray(Image.open(f).convert('L'), float)
    lv = (g[:-2,1:-1]+g[2:,1:-1]+g[1:-1,:-2]+g[1:-1,2:]-4*g[1:-1,1:-1]).var()
    print(f'{lv:8.1f}  {f}')
```

拉普拉斯方差 = 清晰度。判定阈值：

| 拉普拉斯方差 | 判定 | 动作 |
|---|---|---|
| > 200 | 清晰 | 直接用 |
| 50–200 | 尚可 | 轻度锐化后用 |
| < 50 | 偏糊 | 走下面的「放大到底有没有用」 |

⚠️ **肖像图天然偏低**。人脸大面积是平滑肤色，本案例中肖像 16 vs 正文图 264，差 16 倍，但**不代表肖像糊**。
判断人脸要看**眼部/轮廓带**的局部锐度，不要看全图数值。

---

## ⚠️ 放大到底有没有用（2026-10-11 实测）

720×960 肖像，测面部区域锐度：

| 方案 | 面部锐度 | 相对原图 | 结论 |
|---|---|---|---|
| 原图 720×960 | 9.93 | 1.00x | 基准 |
| Lanczos 放大到 1080 | 3.83 | **0.39x** | ❌ 越放越糊 |
| Lanczos + Unsharp(2.0,130%) | 10.57 | **1.06x** | ⚠️ 等于没变 |
| Lanczos + 对比度 1.08 | 10.19 | 1.03x | ⚠️ 等于没变 |
| 放大到 1440 + 锐化 | 4.95 | 0.50x | ❌ 更糊 |

**原理**：拉普拉斯方差衡量的是**真实细节**。纯插值不产生新细节，只会放大已有噪点。
所以"放大 + 锐化"的天花板大约就是 **1.0x**，别指望它救画质。

**但正文配图反而能大幅提升**，因为缩到公众号最佳宽度会减少像素密度：

| 方案 | 锐度 | 体积 |
|---|---|---|
| 原图 1280×720 | 426 | 107KB |
| 缩至 **1000px** + USM(1.5, 90%) | **1510（3.55x）** | **70KB** ✅ 清晰且更小 |
| 缩至 1200px + USM | 1022（2.40x） | 92KB |

**肖像要用小倍率**（大倍率反而降）：

| 方案 | 锐度 | 体积 |
|---|---|---|
| 原图 720×960 | 16.1 | 71KB |
| → **960×1280** + USM(2.0, 110%) | **17.8（1.11x）** | **93KB** ✅ |
| → 1080×1440 + USM(2.0, 130%) | 14.4（0.89x） | 114KB ❌ |

⚠️ **肖像图天然偏低**。人脸大面积是平滑肤色，本案例中肖像 16 vs 正文图 264，差 16 倍，但**不代表肖像糊**。
判断人脸要看**眼部/轮廓带**的局部锐度，不要看全图数值。

**真正有效的三条**：

1. **换源**（收益最大）— B站优先选 1080P60 / 高码率。720P→1080P 是源头提升，任何后期都比不了
2. **换时间点** — 取说话**前 1.5 秒**，避开头部晃动帧
3. **AI 超分** — Real-ESRGAN 可到 1.3–1.6x，但**本机实测跑不通**（torch 在 macOS ARM + Python 3.13 无预编译轮子，装完 dylib 缺失）。
   要用需先配独立环境；且**人脸慎用**，可能"编"出不存在的细节。

## 📐 本项目推荐参数（实测有效）

```python
from PIL import Image, ImageFilter
# 正文配图：缩到 1000px + 轻锐化 → 3.55x 锐度，体积降 35%
im = Image.open(src).resize((1000, 562), Image.LANCZOS).filter(ImageFilter.UnsharpMask(1.5, 90, 2))
im.save(dst, "JPEG", quality=88, optimize=True, progressive=True)

# 肖像：放大到 960×1280 + 中锐化 → 1.11x（不要超过 1.5x 倍率）
im = Image.open(src).resize((960, 1280), Image.LANCZOS).filter(ImageFilter.UnsharpMask(2.0, 110, 2))
im.save(dst, "JPEG", quality=88, optimize=True, progressive=True)
```

## 公众号图片规格

| 项 | 要求 | 原因 |
|---|---|---|
| 宽度 | ≤ 1000px | 超过会被重压 |
| 单图体积 | ≤ 100KB（base64 后） | 超了会丢图 |
| 总像素 | ≤ 600 万 | 平台硬限制 |
| 格式 | JPEG quality 80 | 体积/画质平衡点 |
| SVG | 必须写死 width/height | iOS 不写尺寸不渲染 |
