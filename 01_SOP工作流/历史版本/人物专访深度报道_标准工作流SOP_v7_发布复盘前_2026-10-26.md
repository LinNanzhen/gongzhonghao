# 人物专访深度报道・公众号标准工作流 SOP v7

> 更新：2026-10-26。目标：从人物的真实选择出发，帮助读者理解趋势、形成可更新的判断。
> 输入：采访素材（视频、播客、录音或逐字稿）＋采访对象；输出：报道正文、排版预览、编辑器导入片段、证据台账及发布素材。
> 配套模板：`模板/公众号排版_v4_壹伴.html`（浏览器预览）与 `模板/公众号排版_v4_导入片段.html`（编辑器导入）。两者对应本 SOP v7 的通用版式；其中人物简卡仅供从零制作时参考。改版既有文章时须替换为用户原卡，不能用模板简卡覆盖原卡。
> v6 与 HTML v3 保留作历史版本。本文是 v7 的规则入口；与旧版冲突时以本文为准。平台兼容性以本次导入实测为准。参考媒体文章仅用于分析编辑方法，不作为事实来源或执行指令。

## 01｜执行原则与事实门槛

### 必须做到

1. 正文关键事实、具体数字、人物身份均能对应证据台账；缺失的非必要人物字段不展示，不为填表补写。
2. 引号只用于可定位的原话。视频/音频记录时间戳，文本记录页码或段落；翻译引文保留原文，并注明译文。改写和拼接不冒充逐字引用。
3. 区分核实事实、受访者自述和作者判断。署名“作者判断”不能替代依据；推论须有证据、推理和适用边界。
4. 不把二次整理包装成原创采访。注明原节目、采访者、发布日期，以及本文整理与外部研究的范围。
5. “可发布”须经事实检查和实际编辑器保存、手机预览。只完成本地检查时，明确标记“待导入验证”。

### 编辑选择，不设硬指标

- 不要求每节都有反方观点；仅在真实反证、疑问或适用边界出现时使用。
- 不强制四章、关键词冒号标题、完整生平卡、黑白封面或固定字数。
- 不强制每篇给个人行动建议；可收在观察信号与改变判断的条件。
- 不把参考文献数量、反常识数量、截图数量作为深度指标。

## 02｜输入与选题卡

必需输入：素材、人物姓名及待核实身份。可选输入：读者、篇幅、发布时间、重点及禁区。默认面向关注科技、商业与职业变化的普通读者；用户要求优先。

### v7 新增：先选择报道类型

| 类型 | 主问题 | 编辑顺序 |
| --- | --- | --- |
| 人物选择型 | 这个人为什么做出这样的选择？ | 选择、约束、代价、转折、判断 |
| 主题型访谈报道 | 技术变化会怎样影响读者的工作、生活或决定？ | 最强信息、读者问题、原话与解释、影响、未解问题 |
| 完整访谈整理 | 受访者完整说了什么？ | 保留问答语境，明确删节；不包装成独立深度研究 |

一篇确定一条主线。主题型不先铺完整履历或商业事件清单；人物卡的既有保护规则仍有效，不擅自移动、隐藏或删改原卡。

选题卡另填：本次新增信息、最强可核验原话、与读者的具体关系、保留的主题、删除的旁支。不要以“人物很有名”替代阅读收益；不要为追求新颖而宣称“首次”。

先填写五项，再研究与写作：

| 项目 | 要回答的问题 |
| --- | --- |
| 读者问题 | 读者目前最需要理解什么？ |
| 人物选择 | 哪次真实选择或事件能解释这个问题？ |
| 初步判断 | 本文拟提出什么可被证据修正的判断？ |
| 阅读收益 | 读前到读后，读者将改变什么认识？ |
| 素材条件 | 原话、关键事实和对照资料是否足以支撑？ |

身份反差、行业变化、争议与可延伸性作为选题线索，不按命中数量机械放行。若关键事实无法核实，缩小论题或改为注明来源的访谈整理；没有新增认识时不硬凑深度报道。

## 03｜获取素材与建立证据台账

优先获取原始节目与逐字稿；可使用当前可用的转写工具，不依赖某一固定 skill。记录节目名称、采访者、对象、录制/发布日期、链接及转写版本。音频转写中的姓名、术语和数字须回听。

在既有 `模板/事实台账.md` 基础上，为本篇建立以下字段；旧模板缺少的列直接补入本篇台账：

| ID | 正文主张/人物字段 | 类型 | 原话与定位 | 来源链接/文件 | 发生时间 | 来源发布日期 | 核验状态 | 对应段落 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| F01 | 待核实内容 | 事实/自述/推论 | 时间戳、页码或段落 | 原始来源优先 | 日期或未明 | 日期 | 已核实/仅自述/有冲突/待核实 | 章节编号 |

### 素材卡与最小主张核验

先从逐字稿建立素材卡：时间戳｜说话者｜原文｜忠实中文转述｜限定条件｜读者关联｜对应画面｜拟用章节。自动转写只是检索底稿；引文、数字和说话者需回听。主持人的问题不得自动归给受访者。记录实际核验方法：二次自动转写、字幕/画面对照、原音频听辨分别注明；不得把重跑转写工具称为已人工回听。仍不能确认的逐字引文改为准确归属的转述或删除，并保留待核实记录。

台账一行只对应一个可判断的主张。交易存在、金额、规模、价格、动机分别核验；不能因其中一项已核实就给整段打勾。旧稿的“已核实”不自动等于本轮重新验证。

预测记录原始发布日期、相对时间、适用前提和估算身份。不同场合的“几年后”不能直接拼成逐年兑现时间表。标题、摘要、图表、图注与正文必须保持相同证据强度；文末免责声明不能修复前文过度确定的说法。

处理规则：
- 已独立核实：可作为事实陈述，保留来源。
- 仅受访者提供：明确写“据其在访谈中自述”；不把引用本身当成事实已证实。
- 作者推论：记录支持材料、推理及可能不成立的情形。
- 有冲突或待核实：继续查证、明确呈现分歧，或从正文删除；不能改称“作者转述”后放行。
- 身份、年龄、排名和金额标明对应时间；历史任职不可直接写成现任。
- 数字记录单位、币种、统计口径和时间区间；区分投资额、估值、承诺金额与实际支出。
- 代词按实际指代检查，不强求多人物文章全篇只用一种代词。

## 04｜研究：围绕问题补证据

输出一份简短研究笔记，覆盖：行业所处阶段、关键证据、一个有解释力的对照（如适用）、主要不确定性、作者暂定判断。

优先原始访谈、官方文件、原始报告与统计；媒体报道用于补充背景或独立核验。记录报告口径，避免将同一新闻的转载当成多个独立来源。对照样本须说明可比性，不能只罗列公司名称。

不要求每篇都写行业综述。资料只服务读者问题；核验耗时超出预期时继续核查或缩小范围，不为工期降低门槛。

## 05｜选择叙事路径并写稿

| 素材类型 | 建议路径 |
| --- | --- |
| 人物经历型 | 关键选择 → 代价 → 转折 → 当下处境 |
| 观点争议型 | 核心主张 → 证据 → 对照与边界 → 作者判断 |
| 行业事件型 | 发生了什么 → 为什么由此人推动 → 行业影响 → 观察信号 |

### 先做标题与章节骨架，再写正文

先输出主标题、导语、章节标题和每节一句新增认识；只读这些也应能复述全文主线。主题型按读者理解顺序重组，不机械跟随访谈时间线。

导语优先：最强具体信息或忠实原话 → 与读者的关系 → 必要节目背景 → 本文问题。首屏不堆抽象框架、履历或数字清单，不编造紧迫期限。

每节推进一个问题，可采用“读者问题 → 原话 → 具体解释 → 可能影响 → 下一问”，不要求五步齐全。不为凑全面而保留所有话题；连续两段仅重复同一判断时合并或删除。

默认 3—5 节，可按内容调整。篇幅建议 2500—4000 字，仅作编辑预算；短素材不扩写凑字数，复杂材料可更长。

正文顺序：小型栏目标识 → 事件/核心问题导语 → 人物卡片（既有卡片原样保留）→ 编号章节 → 判断与观察信号 → 来源与系列导航。

### 章节标题：01、02、03 模式

- 正文章节从 01 连续编号，用两位数字；编号独立一行，下方放具体标题。
- 统一左对齐。编号使用低饱和品牌金；标题用深色，最多两行。
- 示例：`01` / `从直播业务走向数据团队`；`02` / `数据瓶颈改变了竞争方式`。示例只是结构演示，真实内容须核查。
- 标题须提供本节独有的信息或推进问题；不强制冒号、专有名词或判断句三者同时成立。
- 导语、人物卡、图注、文末来源和导航不参与章节编号。

### 语言与强调

开头直接进入有依据的事件或问题，不编造反差。保留具体选择、动作和代价；不虚构现场、心理或作者体验。“我们”可自然使用，不强制“大伙/咱”。参考 `模板/禁用词表.md` 做编辑检查，最终按语境判断。

390px 手机视口以 2—4 行段落为主，超过 6 行时检查语义拆分；这不是硬性字数限制。连续单句段落过多时合并，避免人为制造紧张感。删除“注意这个推理”“藏着钥匙”等没有新增内容的引导语。

作者判断应指向证据缺口或解释，不替人物读心。重点检查“认输、仅剩、唯一、每一次、必然、从来、都会”等强词。电影类比不是技术机制证据，预测不是事实，算力合作不等于股权投资，未来货币变化不等于存款清零。

正文加粗优先留给关键结论和必要数字；人物首次出现可加粗，不对每次人名、机构名机械加粗。每段通常不超过一处强调。原话引用与作者解读分段，不重复设置金句高亮和引用框。

结尾回答或深化开头问题，留下一个有依据的未解问题，或给出能改变判断的观察信号。不重新逐节总结，不强行升华，不默认增加行动清单。

## 06｜人物卡与配图

### 人物卡片：既有卡片原样保留

用户已有的人物卡片属于受保护内容。优化正文排版或截图时，默认完整保留卡片的文字、履历字段、头像、图片数据、布局、尺寸、颜色、边框及其他样式，不压缩成简卡、不删减信息、不替换头像、不把左右布局改成上下布局。只有用户明确要求修改人物卡片时，才按指定范围调整；改布局时按下方《人物卡手机端尺寸》执行。

- 改版时保留原卡完整 HTML 区块，在预览版与导入片段中原样复用；正文的通用样式调整不得覆盖卡片。
- 人物卡不受本 SOP 其他通用字号、图片处理、简化样式或布局建议强制改写。若发现事实问题或导入兼容问题，单独说明，不以排版优化为由静默修改。
- 完成后比较改版前后的卡片 HTML 和头像数据，并检查手机显示，确认没有意外改动。
- 从零制作且没有原卡时，可使用配套模板中的简卡作为起点；这不是既有卡片的替换规则。

### 人物卡手机端尺寸：上下布局为默认

左右分栏在长生平文本下必然把头像压小，这是反复出现的问题，不是偶发。实测记录：

| 案例 | 布局 | 375px 视口 | 390px 视口 | 问题 |
| --- | --- | --- | --- | --- |
| Larry | 左右，头像列 38% | 头像 133px 宽 | — | 长生平文本下侧栏被压死 |
| 3Blue1Brown（改版前） | 左右，头像列 50% | 头像 161×203px | 头像 175×221px | 单元格 464px 高、照片仅 221px 高，照片下方 243px 空米色；头像像贴在框里的小邮票 |
| 3Blue1Brown（改版后） | 上下，头像通栏 | 头像 335×226px | 头像 350×236px | 宽度 2.0 倍、面积 2.14 倍，死空间归零 |

制作规则：

1. **布局**：头像通栏在上、文字全宽在下。履历字段超过三行一律用上下布局；履历确实很短时才评估左右布局，且仍须按第 5 条验收。
2. **头像图**：`<img style="width:100%;height:auto;display:block;margin:0;">`。禁止固定像素宽高，禁止给头像单元格设背景色再让照片悬在其中。
3. **源图裁切**：从原帧按 3:2 横幅裁切并聚焦人脸，人脸占画面宽度 45%–55%；源图宽度 ≥ 头像 CSS 宽 × 2（390px 视口下卡片约 350px，源图 ≥ 700px）。裁切来源的时间戳写进卡片脚注，如"图片截自原视频 37:10（已裁切为通栏）"。
4. **字号下限**（CSS px，低于此值在手机上即显小）：姓名 ≥ 18；职位/副标题 ≥ 13；字段标签 ≥ 12；字段内容 ≥ 15（贴近正文 16px）。
5. **验收**：新卡或获准改布局的卡在 375px / 390px / 430px 三档视口截图，实测头像 CSS 宽 ≥ 视口宽 − 60px（即基本通栏），且照片高宽比与源图一致（误差 < 3%）。优先读取实际元素尺寸，必要时用标记条和像素扫描辅助；既有卡片按原样保护与显示完整性验收。

### 先定图片用途，再找图

| 用途 | 图形选择 | 要求 |
| --- | --- | --- |
| 认识人物 | 真实人物照 | 标注具体图源，记录可用依据 |
| 呈现原始场景或原话 | 视频截帧 | 定位时间戳，检查字幕与上下文 |
| 解释阶段 | 时间线 | 年份、事件有来源 |
| 解释差异 | 对照图 | 口径可比，说明差异 |
| 解释机制 | 关系图/流程图 | 区分证据与作者分析框架 |

大纲阶段为每张图填写“要解释的问题”。竖向概览图优先于手机难读的多列长句横图；每张图只承担一个主要任务。关键文字应在正文宽度直接读清，不以“可以点开放大”代替验收。关系图中的假设、作者归纳与已证事实分开标识，不能用确定箭头掩盖证据缺口。

概览图可按问题或机制分组；无逐节点来源与一致时间基准时，不生成逐年预测路线图。截图按原话定位选取，不为固定配额重复插入人像。新智元等样稿的品牌标志、署名与装饰不复制为本账号身份。

没有解释任务的图片不必添加。AI 插画必须标注“AI 生成示意”，不冒充采访现场或真实人物照片；公开可见不等于自动获得转载许可。截图保留必要来源和版权署名，不为美观裁掉来源标记。

### 高清截图流程

1. **检查原片**：优先获取合法可用的 1080p 或 4K 素材，读取文件实际分辨率，不只相信文件名。现有素材不足时明确清晰度上限，不把放大后的尺寸称为新增细节。Larry 案例的 1280×720 只是该片实测分辨率，不是通用标准或上限。
2. **定位并直接取帧**：按原话或场景时间戳从视频提取原始帧，不截播放器窗口，不对截图反复截图。优先选对焦准确、镜头稳定、主体运动较少的画面。若调整取帧时刻，同步更新图注时间戳，保持语义一致。
3. **保留 PNG 原帧**：按视频原始分辨率导出 PNG，保存到案例的 `截图/高清原帧/`。不默认缩到 1000px，不重复有损压缩；记录素材文件、时间戳、分辨率和输出文件。
4. **裁切和发布副本分开**：默认保留完整画面。确需裁切时保存独立副本，检查裁切后的有效像素，不把小区域放大冒充高清。人物卡头像和封面不随正文截图优化自动修改。
5. **按画质控制体积**：不设单图必须低于 100KB 的门槛。图片含小字、图表或字幕时优先 PNG；照片确需减小体积时，可从 JPEG 质量 90—95 开始测试，保留 PNG 母版，避免反复保存 JPEG。上传限制以当前编辑器实际要求为准。
6. **锐化仅作可选辅助**：原帧优先，必要时在最终缩放后轻度锐化；出现白边、噪点或伪影则减弱或取消。不得用生成式补细节冒充真实视频证据。锐度数值只辅助判断，不替代人脸、文字和上下文检查。
7. **替换与验收**：预览和导入片段同步替换正文图片，保留正文、图注与人物卡；若画面或时间戳变化则据实更新图注。检查所有图片加载、移动端显示和横向溢出，再验证编辑器保存及手机预览后的画质。

base64 仅是编码方式，不提升清晰度，也不额外损失原图像素；文件体积会增加。不得把成功内嵌等同于微信转存或上传成功。

## 07｜视觉规范与 HTML 输出

### 统一视觉参数

| 元素 | v7 默认值 |
| --- | --- |
| 页面 | 白底；预览最大宽 680px；正文左右留白 20px |

微信原生标题与作者信息已经展示时，正文不重复一整套标题和元信息。预览模板因此默认从栏目与导语开始。

### 两种文件，职责明确

1. `*_排版预览.html`：完整 HTML 页面，供浏览器审阅。
2. `*_导入片段.html`：只有正文片段，无 doctype/html/head/body/style/script；正文使用内联样式与 section/p/span 等简单结构。

两份正文从同一内容生成，避免手动维护导致漂移。项目模板对应 `公众号排版_v4_壹伴.html` 和 `公众号排版_v4_导入片段.html`。

v7 主动避开 div、class、id、flex、grid、position、渐变、脚本及事件属性，作为保守导出策略；这不是声称所有平台版本必然删除它们。也不依赖媒体查询。

图片在编辑器中上传并确认转存后使用平台链接；base64 仅在当前导入路径实测通过时选用，不承诺自动接管。正式稿不得保留本地路径、失效链接或占位符。示意图可导出为静态图片并在手机检查。

模板中的【】为待填写项，图片区域为文字提示，不含虚假图片链接。模板可以保留占位符，正式稿不可以。

## 08｜标题、封面与来源

提供 5 个标题备选，按事件、人物选择、关键判断、反差、读者问题等角度变化；不要求关键词堆叠。标题必须与证据和正文一致。年龄、金额、排名仅在有意义且已核实时使用。长度以实际列表预览为准，约 30 字仅作编辑参考。

封面优先采用真实人物图片或有解释力的视觉。黑白/低饱和可作为默认方向，不强制每期使用。主封面可先以 900×383px 制作，同时检查列表与分享裁切；需要方图时另行导出，最终按当前平台要求调整。记录图源与处理方式。

正文关键事实可用 [1]、[2] 简短标记，文末按实际引用列来源。格式：`[编号] 作者/机构：《标题》，发布日期，链接；涉及原话时补定位。` 一条来源可支持多处内容，但每条关键主张必须有明确对应。

用户要求隐藏文末来源区时，可调整公开展示方式；内部核验台账仍须保留，不能因此取消核查。

## 09｜交付与验收

默认交付：正文 Markdown、浏览器预览 HTML、导入片段 HTML、事实/主张台账、正文引用来源、5 个备选标题及封面。摘要与分段长图按需提供，不为凑清单固定生成。长图是备用方案，使用前检查文字大小与阅读体验。

### 高清预览与长图导出

按目标手机视口排版，渲染时采用至少 2 倍像素密度（如 `deviceScaleFactor: 2`），默认保存为 PNG。例如 390px 视口对应 780px 宽的 2 倍像素图；CSS 字号与布局不随之放大。不要把已经生成的低分辨率长图直接拉大。篇幅过长时分段渲染或导出，避免截图尺寸限制导致截断，并检查段间连续、无漏行。

高像素密度改善文字和页面渲染，不会恢复原视频缺失的细节。每次 HTML 图片或版式更新后，应重新生成长图与局部预览；检查实际像素尺寸、图像加载和文字清晰度。

### 测量实际渲染，不固化单次环境偏差

历史环境曾观察到窗口与布局视口不一致、图片比例异常，但不将“窗口一律减 20px”或“body 必须固定宽”当通用浏览器规则。用实际 `innerWidth`、元素边界尺寸、`naturalWidth/naturalHeight` 和计算样式定位问题；确保图片显示比例与源图一致（误差 < 3%）。优先设置浏览器明确 viewport，在 375/390/430px 检查，不靠肉眼或窗口启动参数猜测。

既有人物卡按原样保护与显示完整性验收；通栏宽度要求只适用于新卡或用户明确授权改布局的卡，不以该要求自动覆盖旧卡。

### 豆包、飞书与编辑器之间的交接

1. 给生成工具提供 SOP、本次选题卡、素材卡/原始转写与样稿编辑分析；样稿只用于结构和视觉参考，评论区不输入正文素材。
2. 首轮完成正文与配图任务表。核验引用、限定词、时间和主体归属后冻结文字。
3. 排版轮仅改变版式。不得擅自润色、缩短引文、删除条件、补充事实或改动人物卡；确需改写则列入变更记录并重新复核。
4. 预览与导入片段从同一正文生成。飞书文档、本地 HTML 和微信草稿分别记录完成状态，不能以其中一个成功代表另两个已通过。
5. 图片上传后核对转存、加载与图注；本地相对路径不视为发布链接。无法上传时交付图片素材清单并明确“编辑器待验证”。

### 首屏、扫读与删稿验收

- 首屏：发生了什么，与读者有什么关系，继续读能获得什么？
- 扫读：只读标题、重点句和图，能否复述主线且不会把预测当事实？
- 删稿：删掉重复判断、无关背景、无依据的心理揣测；每节有新的认识。

### 内容检查

- [ ] 阅读收益明确，正文回答选题问题；不以身份标签代替论证。
- [ ] 关键事实、数字、身份及原话可追溯，核验状态清楚。
- [ ] 自述、推论与事实分开；没有虚构场景或强制反对。
- [ ] 现职/历史身份、年龄、排名和数字口径有时间依据。
- [ ] 既有人物卡的文字、头像数据和完整 HTML 样式与原版一致；配图承担明确任务。
- [ ] 章节连续编号 01、02……；标题具体且版式统一。
- [ ] 无【】等模板占位内容，无断链或未替换图片。

### 本地排版检查

- [ ] 导入片段无页面外壳、外部样式、脚本、事件属性及本 SOP 禁用的布局依赖。
- [ ] 用 HTML/CSS 解析或人工检查属性与样式；不能只靠大小写敏感的简单字符串判断。
- [ ] 预览与导入片段的正文一致。
- [ ] 在 375px、390px、430px 宽度检查换行、留白与横向溢出；图片文字能读。
- [ ] 既有人物卡 HTML 与头像原样保留；新卡或获准改布局的卡按通栏规范验收。实际视口准确，图片显示比例与源图一致（误差 < 3%）。
- [ ] 截图保留原始分辨率 PNG 母版，来源与时间戳可追溯；无为满足 100KB 而强行压缩。
- [ ] 正文换图未意外修改人物卡、头像或封面；预览和导入片段图片一致。
- [ ] 提供长图时，已用至少 2 倍像素密度重新渲染，核对实际尺寸、完整性和可读性。

### 编辑器验收（本地预览不能代替）

1. 按当前可用方式导入：从浏览器复制正文，或在已确认支持的源码入口粘贴片段。
2. 检查图片、段落与引用样式；需要时上传替换图片。
3. 保存草稿，再次打开确认未丢内容和样式。
4. 手机预览标题、章节编号、人物卡、图片与文末来源。
5. 记录日期、浏览器、编辑器/插件、导入方式、结果和遗留问题。通过后才标记“导入验收通过”；发布仍按用户授权执行。

模板首次使用应做一次完整验收，之后每篇至少检查保存后内容与手机预览。未执行时明确交付“本地完成，编辑器待验证”。

## 10｜时间预算与复盘

素材齐全且核验顺利时，可把 60—90 分钟作为快速制作预算；复杂研究、图片授权与平台排障另计，不承诺固定完成时长。

发布后结合可获得的数据与反馈，记录：标题吸引来的读者是否匹配、哪里难懂或中断、哪张图有效、哪些判断需更新。每次只优先调整最有证据的一两个问题，不把单篇数据波动直接归因于某个排版细节。
